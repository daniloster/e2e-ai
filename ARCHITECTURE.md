# Architecture — e2e-ai

The rules every change in this repository is checked against. The why behind each engine decision is
in `docs/20261118-e2e-ai-cucumber-small-models/` (decisions D-n, failure modes F-n).

## 1. Layout

```
e2e-ai/
├── packages/                    # the product
│   ├── e2e-ai/                  # @pn/e2e-ai: engine library (+ default report templates in templates/)
│   ├── e2e-ai-cli/              # @pn/e2e-ai-cli: the `e2e-ai` command
│   └── vscode-e2e-ai/           # VS Code extension (bundles the engine's routineSyntax.ts)
├── e2e/                         # the example suite (what a team owns)
│   ├── e2e-ai.config.json       # model endpoint, docs, API URL, targets/integrations, media, reports, benchmark
│   ├── docs/                    # API reference + app guide (Markdown) — the model's only app knowledge
│   ├── features/  routines/     # Gherkin + #tags + @routine; reusable step groups
│   ├── reports/templates/       # report layouts (each also the model's brief); runs/ is generated
│   ├── playwright/              # generated by `e2e-ai playwright init`
│   └── .plans/plans.json        # the plan lockfile (reviewed in PRs)
├── apps/  apps-modules/  tools/ # the Pocket Notes demo app (web + React Native) and its modules/assets
└── docs/                        # investigations
```

- npm workspaces: `apps/web`, `apps-modules/*`, `packages/*`, `tools/*`. `apps/mobile` is standalone
  (own `npm install`; `file:` links to `apps-modules/*`).
- Source-only TypeScript packages (`main: src/index.ts`), run by Node 22's type stripping: relative
  imports carry the `.ts` extension; no enums or parameter properties.

## 2. Engine pipeline (`packages/e2e-ai`)

```
.feature ──dialect.ts──► standard Gherkin ──@cucumber/gherkin──► scenarios (+ Background flags, lines)
@routine ──routines.ts (routineSyntax.ts)──► concrete steps with origin + scope
docs/*.md ──docs.ts──► catalog: endpoints, routes, glossary, examples (→ JSON-schema enums)
step ──planner.ts (2 constrained LLM calls + guards)──► actions ──cache.ts──► plans.json
actions ──runner.ts──► integration (drivers/*, mcp/*) ──► page source / taps / API calls
results ──report.ts / benchmark.ts──► report.json + HTML templates (view plan + checked prose)
```

- **Model port** (`llm.ts`): OpenAI-compatible (`response_format: json_schema`) or Ollama native.
  Output is always schema-constrained; builds without structured output (e.g. MLX tags) are rejected
  by `doctor`.
- **Guards** (`planner.ts`, `grounder.ts`, `runner.ts`) are generic and deterministic; changing one or
  the prompts bumps `PLANNER_VERSION`, which expires cached plans.
- **Integrations** (`drivers/index.ts`): `mcp` (any server with the `ui_*` tools; ours: `web-mcp`,
  `rn-mcp`), `playwright-mcp`, `appium`, `maestro`, `rn-bridge`; Playwright Test via `playwright.ts`.
  All return the same `UiElement` page source; route names resolve to URLs or deep links per platform.
- **Roles** (`roles.ts`): one role vocabulary for every platform (iOS types, Android classes, Maestro,
  HTML/ARIA), overlays (alerts, dialogs, permission prompts, sheets) as named elements, config
  overrides (`ui.roles`), and the OS prompt texts the `@global` planner may use.
- **Clouds** (`cloud/`): `cloud.ts` (credentials, hubs, uploads, capabilities, remote browsers,
  session status/links), `tunnel.ts` (Sauce Connect, BrowserStack Local), `maestroCloud.ts` (scenarios
  compiled into Maestro flows), `fakeCloud.ts` (local stand-in for both vendors, dev/test only;
  `npm run e2e:cloud:check`). Credentials never reach logs, reports or caps files.
- **The model never judges results**: assertions are deterministic; plan repair excludes assertions;
  report prose is verified against the run data.

## 3. Code style

- Function declarations, named exports only (lint-enforced; tooling configs excepted).
- Classes only for things that own native resources and for error types.
- Prettier (single quotes, trailing commas, 100 columns); strict TypeScript everywhere
  (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`).
- Exact dependency versions (`save-exact`); a version change is its own reviewed change.

## 4. Tests

- Co-located `*.test.ts(x)`; Vitest for workspaces (`vitest.workspace.ts`), Jest inside `apps/mobile`.
- Engine behaviour that came from a failure mode keeps a test that fails if its guard is removed.
- Parsers for every integration's page source have fixture tests (XCUITest XML, UiAutomator XML,
  Maestro hierarchy, Playwright ARIA snapshot).
- `npm run lint && npm run typecheck && npm test` must pass before a change is done.

## 5. Demo app (Pocket Notes)

- `apps/web/app.html` (notes app), `apps/mobile` (React Native, debug and e2e builds carry the e2e
  bridge and the e2e deep links; the e2e build bundles its JS for device clouds), `apps-modules/fixture-api` (in-memory API with `/__test/*` seeding).
- `apps-modules/core` stays pure and deterministic (lint-enforced); copy comes from
  `apps-modules/i18n` (en-GB source, es and pt-BR with identical keys).
- Same `testID`s on web and mobile so one plan replays on both.
